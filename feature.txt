inspectrum ng v0.5.4-rc0
========================

Forked from inspectrum v0.4.0.


Unreleased
----------
New features:
- Wheel scrolling reworked around time, the axis you actually navigate:
    * wheel (and Alt+wheel, and a side / tilt wheel) scrolls time
    * Shift+wheel scrolls frequency -- only does anything when the
      spectrogram is taller than the view
    * Ctrl+wheel still zooms
  A notch scrolls a tenth of the view instead of Qt's default few
  pixels, and fractional deltas from high-resolution wheels and
  touchpads are accumulated rather than rounded away to nothing.
  INSPECTRUM_WHEEL_DEBUG=1 logs what each wheel event reports.
- Data format selectable in the app: a "Data format" combo next to the
  sample rate offers the same set as the -f/--format command line
  option (Auto / cf32 / cf64 / cs32 / cs16 / cs8 / cu8 / f32 / f64 /
  s16 / s8 / u8 / wav). Picking one re-reads the open file through that
  adapter; "Auto" goes back to the file extension. A format the file
  can't be read as reports the error and rolls back to the previous
  one. The choice is stored in .isession files, and -f still works and
  now shows up in the combo.
- Cursor placement without dragging: shift+click moves the nearest time
  cursor to the pointer, shift+drag sets the selection outright -- the
  horizontal extent becomes the time selection and, when the bandwidth
  cursors are on, the vertical extent becomes the measured band. The
  right-click menu gains "Selection start here" / "Selection end here".
- Bandwidth selection: horizontal cursor pair on the spectrogram, the
  frequency counterpart of the existing time cursors. Drag either line
  to move it, or the band between them to move both. The plot shows the
  frequency of each line and the bandwidth between them; the controls
  panel adds Freq high / Freq low / Bandwidth / Centre read-outs and a
  "Set tuner to selection" button that moves the tuner onto the measured
  band. Cursor positions are stored in Hz, so they stay on the signal
  while scrolling and when FFT size / Y zoom change, and they are saved
  in .isession files. Opacity follows the existing Grid opacity slider.

Bug fixes:
- "Optimizing FFT plans (first run)..." ran on every run: needsPreWarm()
  inspected the in-process plan cache, which is empty at every startup,
  so the answer was always yes and the modal dialog was forced up with
  minimumDuration(0). It now probes the imported wisdom with
  FFTW_WISDOM_ONLY and keeps the plans that probe produces, and the
  dialog only appears if planning really takes longer than 500ms.
  Startup with usable wisdom: 5.5s -> 0.03s.
- Frequency scale and SigMF annotation boxes ignored the Y zoom / crop
  window: with Zoom Y > 1x (or Crop to tuner) the tick labels and the
  annotation rectangles were placed as if the whole FFT were visible.
  Both now use the same bin<->pixel mapping as the spectrogram image.


v0.5.4-rc0
----------
UI fixes:

v0.5.3
------
Bug fixes:
- Fix crash (SIGILL) when adding derived plot on various CPUs.
  rc1: CPUs without AVX-512 crashed (reported by Norbert DL8LAQ, issue #1).
  rc2: CPUs with AVX but without AVX2 also crashed.
  Root cause: liquid-dsp dotprod compiled for a single SIMD level, or
  AVX variant compiled with AVX2+FMA flags.
  Fix: liquid-dsp fork (bvernoux/liquid-dsp) with runtime SIMD dispatch.
  All variants (portable/SSE4.2/AVX2+FMA/AVX-512) compiled, best selected
  via CPUID at startup. AVX-only CPUs use SSE4.2 fallback.
- Hardened thread safety and shutdown (TunerTransform QMutex, PlotView
  destructor waits for worker threads, addPlot null guard, TracePlot
  worker exception guard).
- New crash diagnostic logger (inspectrum_crash.log next to executable).
  Logs OS/compiler/Qt info, timestamped entries, and on crash: exception
  code, address, stack trace (Windows dbghelp / POSIX signals). Logs
  clean exit confirmation.

Performance:
- TunerTransform::work(): mutex narrowed to parameter snapshot only
  (~1us); FIR computation (~50-200us) runs lock-free. Eliminates UI
  stutter during tuner drag with derived plots.
- Noise floor: scratch buffer reuse (eliminates up to 2048 heap allocs
  per tile), adaptive nth_element + min_element. 1.14x-1.73x faster.

New files:
- crashlog.h/cpp - crash & diagnostic logger (SEH/signals, stack
  traces, OS/compiler/Qt info).


v0.5.2 (reassigned spectrogram & quality)
------------------------------------------
Features:
- Reassigned spectrogram: 3 FFTs per column (h, t*h, h') with energy
  redistribution to TF centroids (Auger & Flandrin 1995). Sharper
  pure tones, better chirp concentration. Threshold 1-120 dB below peak.
- Synchrosqueezed: 2 FFTs per column, frequency-only reassignment.
  Preserves time grid (invertible). 33% cheaper than reassigned.
- TracePlot min/max decimation: per-pixel-column min-to-max line.
  Preserves OOK edges, FSK steps, fast transitions at all zoom levels.

Bug fixes:
- Noise floor: percentile interpolation (nth_element range).
- Ctrl+wheel zoom anchors on cursor X (was viewport center).
- View position preserved across FFT/zero-pad/overlap/zoom/crop changes.
  Root cause: updateView(reCenter=true) clobbered scroll position with
  stale wheel-anchor data. Fix: reCenter only for wheel zoom; other
  paths use save => updateView(false) => restore.
- Zoom Y no longer pulls toward bottom. Pixel-to-bin mapping now accounts
  for crop window (yTop + visibleBins). Also fixes jumpToFreq().
- ThresholdPlot bin/hex/dec overlay refreshes on Power Max/Min change
  (powerMax affects filter gain; bitsCacheDirty was never set).
- Tuner BW/centre changes update derived plots in real-time during
  drag, not only on mouse release.

New files:
- reassigned.h/cpp - reassigned & synchrosqueezed TFR engine.


v0.5.1 (advanced spectrogram & signal analysis)
------------------------------------------------
Features:
- FFT overlap control (0%, 25%, 50%, 75%, 87.5%). 4x more columns at
  75% overlap, 8x at 87.5%.
- Window function selector (6): Hann, Hamming, Blackman-Harris (-92 dB
  sidelobes), Kaiser (beta 0-30), Flat-top, Rectangular.
- Extended zero-padding (1x to 64x).
- Averaging modes (5): Off, Linear, Exponential (alpha decay), Max-hold,
  Min-hold. Max/Min use O(n) monotonic deque.
- Noise floor estimation & subtraction: subtract (median), subtract
  (percentile), normalize. Per-frequency-bin.
- Colormap selection (6): Default, Viridis, Inferno, Turbo, Magma,
  Grayscale.
- Cursor lock (prevent accidental dragging while scrolling).
- Grid opacity controls all cursor elements; opacity 0 fully hides.
- Zoom Y works in crop-to-tuner mode (up to 32x).
- Scrollable controls dock, sized to fit at launch.
- Window starts at 50% screen width, 80% height, centered.
- WAV file support (RIFF/WAV, IQ 2-channel, PCM 8/16/24/32-bit and
  IEEE float, SDR++ compatible).

Bug fixes:
- Annotation list cleared on new file load.
- Tuner position bounds-checked on session load.
- Session load blocks signals during reset phase.
- Derived plots share correct stride with spectrogram.
- QPixmapCache cleared on stride change (FFT size, zoom, zero-pad,
  overlap).
- Pre-existing warnings resolved (%zu, memset on complex<float>, unused
  vars) under -Wall -Wextra -Wpedantic.

UI:
- TFR mode combo (Standard / Reassigned / Synchrosqueezed).
- Reassign threshold spin (visible only for non-Standard modes).
- Avg mode combo shows/hides relevant sub-controls (slider, alpha spin).
- Kaiser beta spin visible only when Kaiser window selected.
- Noise percentile spin visible only when percentile mode selected.
- In-app note: derived plots independent from FFT settings.
- All new settings persisted in QSettings and .isession.
- TFR mode always starts at Standard (experimental, not persisted).

New files:
- windowfunctions.h/cpp - 6 window types, precomputed coefficients.
- colormaps.h/cpp       - 6 colormap LUT generators (256-entry RGBA).
- noisefloor.h/cpp      - per-bin noise floor estimation & subtract.
- averaging.h/cpp       - 5 averaging modes, monotonic deque optimization.

Performance (cumulative)
------------------------
- FFTW plan cache (FFTW_MEASURE + wisdom persistence + pre-warm at startup).
- Deferred tuner/zoom updates, ThresholdPlot bit cache, debounced
  QSettings writes.
- Pre-allocated reusable buffers (FFT tile, sample, linear, liquid-dsp).
- Adaptive tile size (~512KB/tile), 128MB caches, FNV-1a hash keys.
- Precomputed constants, FFT normalization by windowSize, partial
  read zero-fill.
- Fast IEEE754 log2f/exp2f approximations (bit-trick, sub-pixel dB
  accuracy).
- Zero-copy FFT API, zero-alloc sample reads, std::fill zero-pad.
- Cache-friendly loop order for colormap (4-7x faster) and averaging.
- Cursor grid: viewport culling, sub-pixel dedup, batched solid lines.
- Correct dB scale (true dBFS, roundtrip-correct dB/linear averaging).
- TracePlot min/max decimation.
- Monotonic deque for O(n) sliding window max/min hold.
- Transpose-process-transpose for cache-friendly max/min hold on
  column-major data.
- Window functions computed once per config change (zero runtime cost).
- Colormaps generated once (256-entry LUT, zero runtime cost).
- Noise floor cached per tile, recomputed only on parameter change.
- Three-level tile cache: fftCache -> enhancedCache -> pixmapCache.
- TileCacheKey includes overlap index for correct cache isolation.
- Reassigned: ~2.5x cost of standard STFT (3 FFTs); synchrosqueezed:
  ~1.8x (2 FFTs).
- Memory-mapped file I/O: 100GB+ files use ~500MB RAM.


Display
-------
Dynamic slider labels, render time stats (min/avg/max), native platform
style (windowsvista/Fusion), SI formatted values, controls rearranged
by workflow.


Build
-----
- MinGW: static linking (libgcc, libstdc++, -mwindows), Qt/runtime
  DLL bundling.
- LIQUID before FFTW link order for static libs.
- Wisdom file next to exe (fallback to AppLocalDataLocation on
  read-only installs).
- Portable: builds on Windows (MinGW/MSVC), Linux, macOS.
- Zero warnings with -Wall -Wextra -Wpedantic on GCC/MinGW; /W4 on MSVC.
